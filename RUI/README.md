# RUI

**RUI** - легковесный UI-фреймворк для Unity с собственной системой вёрстки, кастомной текстовой разметкой и процедурной генерацией геометрии в батчи. 

Фреймворк создавался с двумя ключевыми целями:
1. **Компонентная модель в духе Unity:** поведение и свойства элементов строятся через композицию компонентов (как `GameObject` и `MonoBehaviour`), а не через жёсткие монолитные классы.
2. **Современная система компоновки:** предсказуемый двухпроходный layout (**Measure & Arrange**), вдохновлённый WPF, Flutter и Avalonia.

---

## 1. Архитектура: Ноды и Компоненты

Во многих популярных UI-системах и языках разметки **узел дерева (нода) и компонент - это одно и то же**:
* В **HTML / XML**: тег `<button>` одновременно является и структурной нодой в DOM, и определяет внешний вид кнопки, и задаёт её поведение при клике.
* Во **Flutter**: виджет `Container` или `Text` - это сразу и узел в дереве элементов, и описание визуализации, и правила расположения.
* В **WPF / XAML**: класс `Button` или `Grid` объединяет в себе логику контрола, геометрию и правила отрисовки.

**В RUI подход принципиально иной:**

### `CanvasElement` - чистый узел дерева
Сам по себе `CanvasElement` не имеет визуального представления, не умеет рисовать себя и **не содержит логики компоновки**. Это легковесный контейнер, который отвечает только за:
* Иерархические связи (`parent`, `children`).
* Хранение итоговой геометрии (`ResolvedTransform`).
* Коллекцию прикреплённых к нему компонентов.

### `CanvasComponent` - логика, визуал и компоновка
Вся функциональность узла собирается из независимых компонентов. Элемент становится кнопкой, картинкой или окном только тогда, когда на него навешиваются соответствующие компоненты:

```text
MyButton {
    Image: color=#2C2C2C borderRadius=4
    Button: normalColor=#FFF hoverColor=#EEE
    SizedBox_Composer: size=(120, 32)
}
```

Любое деление компонентов на «визуальные» или «поведенческие» условно - в системе есть лишь базовый класс `CanvasComponent`. Разработчик может свободно создавать любые компоненты под свои задачи.

Единственное важное архитектурное разделение в RUI: **компоновщики (Composers)** и **все остальные компоненты**.

## 2. Layout-система: Measure & Arrange

Вёрстка в RUI работает по классическому двухпроходному принципу:
> **Ограничения спускаются вниз. Размеры поднимаются вверх. Родитель задаёт позицию.**  
> *(Constraints go down. Sizes go up. Parent sets position).*

Система разделена на два контракта:
* `IMeasurable` - вычисляет и сообщает наверх желаемый размер (`DesiredSize`) в рамках переданных ограничений (`SizeConstraints`).
* `IComposer` - расставляет дочерние элементы внутри выделенного прямоугольника (`ArrangeRect`).

### Фаза 1: Measure (Снизу-вверх)
1. Родитель вызывает `child.Measure(constraints)`, передавая ограничения (свободное пространство, максимум, минимум или фиксированный размер).
2. Потомок опрашивает своих детей и возвращает свой `DesiredSize`.
3. Полученный размер кэшируется в `CanvasElement.DesiredSize`.

### Фаза 2: Arrange (Сверху-вниз)
1. Родитель, зная желаемые размеры детей, распределяет для каждого ребёнка его локальный прямоугольник: позицию относительно родителя (`pos`) и размер (`size`).
2. Вызывается `child.Arrange(finalRect)`.
3. Элемент фиксирует свой итоговый трансформ (`ResolvedTransform`).
4. Если на элементе есть компоновщик (`IComposer`), он запускает распределение позиций уже для своих прямых детей.

> **Поведение по умолчанию:**  
> Если на узле **нет** компонента-компоновщика:
> * В фазе `Measure` узел опрашивает всех детей и запрашивает максимальный габарит среди них.
> * В фазе `Arrange` все дети по умолчанию растягиваются на полный размер узла в локальных координатах `(0, 0)`.

## 3. Стандартная библиотека компоновщиков

RUI поставляется с набором готовых компонентов компоновки («стандартная библиотека»). Их использование **не обязательно** - архитектура полностью открыта, и при необходимости разработчик может реализовывать собственные алгоритмы вёрстки (сетки, таблицы, круговые меню), просто создав компонент с интерфейсами `IMeasurable` и `IComposer`.

### `Stack_Composer`
Линейный стек элементов (аналог Flexbox / `StackPanel` / `Column` / `Row`).
* **`axis` (`Vertical` / `Horizontal`):** направление выстраивания элементов.
* **`spacing`:** отступ между соседними элементами.
* **`padding`:** внутренние поля (`float4: left, top, right, bottom`).
* **`fillCross` (`None` / `Child` / `Parent`):** поведение по поперечной оси (сохранять исходный размер, подогнать всех под самого крупного ребёнка или занять всё пространство родителя).
* **`alignMain` (`Start` / `Center` / `End`):** выравнивание вдоль главной оси (например, прижать действия к правому краю через `End`).
* **`reverse`:** инвертирует порядок обхода элементов.

### `Anchor_Composer` и `Anchor`
Многослойное и абсолютное позиционирование (аналог `RectTransform` с анкерами или `Stack` + `Positioned`).
* Вешается на родительский узел-контейнер (`Anchor_Composer`).
* Дочерние элементы могут иметь компонент `Anchor`, где явно указываются привязки: `left`, `top`, `right`, `bottom`, `width`, `height`.
* Элементы без компонента `Anchor` по умолчанию растягиваются на всё доступное пространство контейнера (удобно для оверлеев и модальных окон).

### `Fill_Composer`
Простой контейнер-заполнитель: растягивает дочерние элементы на всю свою область с учётом отступов `padding`.

### `SizedBox_Composer`
Явное задание габаритов:
* Если `size > 0` - навязывает фиксированный размер по указанной оси.
* Если `size <= 0` - работает в режиме `auto`, рассчитывая размер по содержимому дочерних узлов.

### `ScrollView`
Компонент скроллируемой области (одновременно является и обработчиком ввода, и компоновщиком `IComposer`):
* В фазе `Measure` даёт дочернему контенту неограниченную свободу по оси прокрутки (`Unlimited`), позволяя ему посчитать свою реальную полную высоту.
* В фазе `Arrange` удерживает вьюпорт в рамках окна, выставляет контенту его честную суммарную высоту и смещает его согласно `scrollPosition`.
* Автоматически добавляет компонент `Mask` для аппаратного отсечения невидимой части.

## 4. Визуальные трансформации: `VisualTransform`

В RUI структура `ResolvedTransform` намеренно является результатом фазы `Arrange` и не редактируется напрямую из пользовательского кода.

Если элемент нужно повернуть (например, стрелочку раскрывающегося списка) или отмасштабировать без поломки общего лейаута, используется компонент **`VisualTransform`**:
```csharp
arrowTransform.angle = model.isCollapsed ? 0f : -90f;
```
Поворот и масштабирование рассчитываются относительно геометрического центра элемента и применяются поверх уже рассчитанного прямоугольника слота в момент формирования матрицы узла.

## 5. Пример разметки (.ui)

Пример описания плавающего окна со списком элементов и контекстным меню:

```text
MyRoot {
    Anchor_Composer:

    // Плавающее окно иерархии слева
    HierarchyWindow {
        Anchor: left=16 top=48 bottom=16 width=250
        Image: color=#2C2C2C borderRadius=6

        ScrollView:
        {
            Stack_Composer: axis=Vertical fillCross=Parent spacing=2 padding=(4, 4, 4, 4)
            LotsContainer:
        }
    }

    // Полноэкранный слой для выпадающих меню (автоматически Fill)
    ContextMenus {
        ContextMenusUI:
    }
}
```
